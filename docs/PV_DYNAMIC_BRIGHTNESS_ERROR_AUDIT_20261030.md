# 动态融合：误检、漏检损失核查

## 当前训练已经提供错误惩罚

`scripts/kaggle_dynamic_brightness.py` 使用 `pvseg/losses.py` 中的类别平衡 BCE + 0.5 Dice，并加 alpha 锚定和 TV 正则。

训练概率为 `p = sigmoid(20 * (F - reference))`。背景像素的 BCE 为 `-log(1-p)`，光伏像素为 `-log(p)`；误报越有信心，背景损失越大；漏掉的光伏概率越低，前景损失越大。Dice 也约束软预测中的误检、漏检。

当前损失没有单独挖掘困难前景和困难背景，也没有真实的大棚像素类别标签。因此，已有分割监督与对大棚混淆的专门训练目标需要区分。

## 反向传播能更新什么

保留原亮度门控后，融合为 `F=(1-alpha)*D+alpha*S_b`。

`D`、`S_b` 及 alpha 的输入图在代码中 detach；只有输出 alpha 的网络可训练。

局部梯度满足 `dF/dalpha = S_b-D`。当两路响应相同，局部融合分数对 alpha 的导数为零；当它们位于当前阈值的同一侧，任何 `[0,1]` 范围内的凸组合都不能跨过阈值。两路分歧时，权重调整可能改变分类。

诊断脚本另用一个误检像素和一个漏检像素执行现有 loss 的反向传播，检查梯度下降能降低误检分数、提高漏检分数，同时确认两个 CAM 没有梯度。这是计算图核查，未更新已训练模型。

## 锁定结果后的事后诊断

复用原始 CAM、亮度门控和已选中的 alpha；独立重建全部 432 组混淆表，与已保存结果精确一致。未重新选择阈值或 checkpoint。

局部动态融合、各方法重校准阈值模式；含大棚的 13 张开发图，三次支持选择分别汇总后取均值：

| 当前错误 | 两路位于阈值两侧，逐像素自由调整 alpha 在理论上可能纠正 | 两路同时位于错误一侧，当前阈值下任何凸组合均无法纠正 |
|---|---:|---:|
| 背景误检 FP | 98.35% | 1.65% |
| 光伏漏检 FN | 94.01% | 5.99% |

当前这组图的 IoU 为 49.80%，光伏 Recall 为 86.06%；背景 FP 平均 726,852，FN 平均 138,592.67。

因此，现有错误中仍有较大的权重优化空间。这里的可能纠正允许每个原始像素自由选择 alpha，范围比实际 56×56、双线性上采样、共享网络预测的 alpha 更宽，不能把比例解释为下一轮必然消除的错误。

这些图是反复观察的开发子集，结论属于事后分析。大棚是整图场景标签，FP 包括该场景中的所有非光伏背景，不能解释成纯大棚像素误检率。三次支持选择不是三个训练随机种子。

## 下一轮建议：只消融困难像素监督

保持亮度门控、alpha 网络、数据划分、训练 episode、步数与 checkpoint 选择规则，比较当前损失与添加类别内困难像素损失的版本。

分别从 GT 为背景的像素中选损失最高的一部分 `H_bg`，从 GT 为光伏的像素中选损失最高的一部分 `H_pv`。分别归一化，避免背景像素数量压过光伏：

`L_hard = 0.5 * [mean_Hbg(-log(1-p)) + mean_Hpv(-log(p))]`

`L_total = L_balanced_BCE + 0.5*L_Dice + lambda_hard*L_hard + L_regularization`

困难像素比例和系数应在训练前固定，或仅依照训练/校准数据选择，不根据这 24 张开发查询图逐次调优。纯背景图只计算背景项。

使用连续 logit 计算稳定的 BCE 并回传梯度；阈值化后的 FP/FN 整数计数用于评价，直接相加不能提供有效梯度。保留光伏困难正像素监督，避免仅靠降低全图光伏响应来减少误报。亮度继续作为辅助输入，不能把所有高亮像素当作大棚真值。

二值光伏标签能把已标注光伏之外的大棚监督为背景，无需先补齐大棚像素类别才能进行这项实验。但要检查训练空间组是否覆盖大棚与光伏的混淆外观；未出现在训练数据中的外观无法获得直接的针对性监督。

同时比较 IoU、Recall、Precision、FP/FN、负图误报及逐图变化。在新的独立空间组上确认收益，避免把开发图的再次改善视为独立验证。

本轮完成核查与诊断，尚未替换训练损失或重训模型。
